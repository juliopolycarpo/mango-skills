# Issues

Follow the repository's issue template. Make the report reproducible and the request testable.

- Title: the observed behavior and where. "`bun build` drops `export *` from barrel files", not
  "Build issue".
- Bug reports: version and environment, minimal reproduction steps, expected result, actual
  result. Paste exact error text in a code block instead of paraphrasing it.
- Feature requests: the use case and current workaround first, the proposed change second.
  Avoid "it would be great if" and speculative benefits.
- Comments: add new facts only, such as a narrower reproduction, a bisected commit, or a
  confirmed workaround. Skip "+1" and status pings without information.
- Keep uncertainty explicit and specific: "reproduces on Linux; macOS untested".
